# FB-001a — Fester Paketname in package.json

**Was:** `package.json` bekommt ein `name`-Feld (`widileads`), und `package-lock.json` ist
einmal konsistent nachgezogen.

**Warum:** Ohne `name` leitet npm den Paketnamen aus dem **Verzeichnisnamen** ab und
schreibt ihn in die Sperrdatei. Auf `main` stand dort zuletzt `widileads-3` — der
Worktree-Name einer Session war ins Repository gelangt. Da jede Session einen anders
benannten Worktree hat, änderte **jedes** `npm install` die Datei erneut: ein
Dauer-Dirty-State, der `git pull --rebase` mit „You have unstaged changes" abbricht und
in jedem Pull Request als Rauschen mitläuft. Im Diff von PR #40 stand
`package-lock.json` genau deshalb.

Mit festem Namen ist die Datei unabhängig vom Verzeichnis und bleibt in allen
Arbeitskopien stabil.

**Geprüft, ob anderswo der Verzeichnisname einsickert:**

| Stelle | Ergebnis |
| --- | --- |
| `composer.json` | `"name": "laravel/laravel"` — fest |
| `vite.config.js` | kein `name`, `root` oder `base` |
| `.env.example` | `APP_NAME=SaaSykit`, `APP_URL=http://localhost` — fest |
| `tests/TestCase.php` | leitet den **Datenbanknamen** aus dem Pfad ab — das ist FB-040 und gewollt; der Wert landet in keiner getrackten Datei |

**Neue Config-Keys:** keine. **Migrationen:** keine. **Tests:** keine — die Änderung ist
nicht durch die Testsuite prüfbar; ihr Beleg ist, dass `npm install` die Sperrdatei jetzt
in jedem Worktree unverändert lässt.
