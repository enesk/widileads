# FB-024a — CI: composer check bei jedem Pull Request

**Was:** `.github/workflows/ci.yml` führt `composer check` (Pint, PHPStan Level 6,
`php artisan test`) bei jedem Pull Request und bei jedem Push auf `main` aus. PHP 8.4,
MySQL 8 als Service, Composer-Abhängigkeiten aus dem Cache.

**Warum:** Bisher war die einzige Absicherung der lokale Lauf der jeweiligen Session.
Merge-Konflikte fängt GitHub — aber nicht den Fall, dass zwei Pull Requests **einzeln
grün sind und sich erst zusammen widersprechen**. Genau das ist passiert: Ein Ticket
legte `leads`-Spalten an, ein anderes prüfte auf deren Fehlen; beide waren grün, und
erst die Reihenfolge des Mergens machte `main` rot. Aufgefallen ist es, als eine dritte
Session ihren eigenen `composer check` nicht mehr auswerten konnte.

**Zuschnitt:** Ein einziger Job, kein npm — die Testsuite rendert ohne gebaute Assets
(`withoutVite()` im `FeatureTest`, nachgeprüft mit entferntem `public/build`). Laufende
Läufe desselben Branches werden bei einem neuen Push abgebrochen, damit die Warteschlange
kurz bleibt.

**Neue Config-Keys:** keine. **Migrationen:** keine.
