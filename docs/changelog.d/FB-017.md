# FB-017 — Theme-Editor

**Was:** Jeder Funnel bekommt ein Erscheinungsbild: vier Farben, Schrift aus einer
Whitelist, Logo-Pfad, Fortschrittsanzeige, Eckenradius und eigene Beschriftungen für
Weiter, Zurück und Absenden. Der Editor liegt unter
`/dashboard/{tenant}/funnels/{funnel}/theme` — links die Eingabefelder, rechts eine
Live-Vorschau im iFrame. **Das Theme geht mit in den Snapshot.**

**Warum:** Ein Funnel, der aussieht wie das Portal, auf dem er eingebettet ist, bricht die
Strecke nicht. Der entscheidende Teil ist aber nicht der Editor, sondern der Snapshot: Die
öffentliche Strecke liest ausschließlich veröffentlichte Fassungen. Ein Theme nur in der
Live-Tabelle wäre dort unsichtbar — und zwar lautlos, der Funnel liefe weiter, nur eben
ungestylt.

**Neue Config-Keys:** keine. Schrift-Whitelist und Fortschrittsarten sind Enums
(`App\Constants\FunnelThemeFont`, `App\Constants\FunnelProgressStyle`), keine freien
Strings — der Wert landet unverändert in einer `font-family` bzw. steuert das Markup.

**Migrationen:** `2026_09_07_091500_create_funnel_themes_table` — ein Theme je Funnel
(Unique-Index auf `funnel_id`), Farben als Hex, Schrift und Fortschritt als Enum-Wert,
Eckenradius ganzzahlig. Mit `down()`.

## Was im Snapshot steht

`snapshot.theme` ist ab jetzt gefüllt statt `null` (Format in
[snapshot-format.md](../funnel-builder/snapshot-format.md)):

| Schlüssel | Inhalt |
| --- | --- |
| `primary_color`, `secondary_color`, `background_color`, `text_color` | Hex, sechsstellig |
| `font` | Enum-Wert: `system`, `inter`, `roboto`, `open_sans` |
| `font_family` | die daraus abgeleitete CSS-Angabe, direkt setzbar |
| `logo_path` | Pfad im öffentlichen Speicher, oder `null` |
| `progress_style` | `bar`, `steps` oder `none` |
| `border_radius` | Pixel, ganzzahlig |
| `button_next_label`, `button_back_label`, `button_submit_label` | aufgelöst, nie leer |

Gelesen wird das über `FunnelSnapshot::$theme` als `ThemeSnapshot`; `cssVariables()`
liefert die Werte fertig als CSS-Custom-Properties. Ohne gepflegtes Theme bleibt der
Schlüssel `null`.

Drei Entscheidungen, die für die Runtime zählen:

- **`font_family` steht mit im Snapshot**, damit die Runtime das Enum nicht kennen muss.
  Fehlt sie in einem älteren Snapshot, leitet `ThemeSnapshot` sie aus `font` ab.
- **Die Button-Texte sind aufgelöst**, nie leer und nie als Übersetzungsschlüssel: Der
  Snapshot muss ohne die Sprachdateien lesbar sein.
- **Unbekannte Werte fallen auf die Vorgabe zurück** (`bar` bzw. `system`), statt die
  Auslieferung scheitern zu lassen.

Die Vorschau ist bewusst eine eigene, in sich geschlossene Darstellung und nicht der
`FunnelRunner`: Der gehört zu FB-020 und braucht einen veröffentlichten Snapshot, den ein
Entwurf mit frisch geändertem Theme nicht hat. Sie bekommt die Werte über die Adresse
mit — so zeigt sie den Stand im Formular, auch bevor gespeichert wurde — und läuft im
iFrame mit `sandbox=""`.
