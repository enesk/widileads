# FB-052a — Währung einer Guthabenbuchung

**Was:** `credit_ledger` bekommt die Spalte `currency` (ISO 4217, drei Zeichen,
`NOT NULL`). `CreditLedgerService` setzt sie bei jeder Buchung; ohne Angabe gilt die
Standardwährung der Installation, ein Guthabenkauf nennt dagegen die Währung, in der
tatsächlich bezahlt wurde. Gelesen wird sie noch nirgends.

**Warum:** `amount_cents` stand ohne Währungsangabe da, obwohl SaaSykit
mehrwährungsfähig ist. Solange nur in einer Währung abgerechnet wird, fällt das nicht
auf — und genau deshalb wird es jetzt nachgeholt, bevor echte Buchungen existieren. Das
Journal ist append-only: Eine spätere Korrektur wäre kein Update, sondern eine Wanderung
über Belege, die man nicht mehr anfassen darf. Die Eigenschaft, die das Journal sonst
schützt, macht die Nachbesserung teuer.

**Die Währung gilt für die ganze Buchung, nicht nur für `amount_cents`.** Ein
Guthabenkonto ist in einer Währung geführt, auch wenn eine Abbuchung selbst kein Geld
bewegt — deshalb trägt jede Zeile eine Währung und die Spalte ist `NOT NULL`. Das
schließt aus, dass eine spätere schreibende Stelle sie stillschweigend offen lässt.

**Der Kauf nennt die Währung der Bestellung**, nicht die Standardwährung.
`BookCreditsOnOrder` liest sie aus der Bestellung; ein Betrag aus einer USD-Bestellung
unter EUR abzulegen wäre genau der Fehler, den die Spalte verhindern soll.

**Migrationen:** `2026_09_07_104500_add_currency_to_credit_ledger_table`. Drei Schritte,
damit die Spalte am Ende ohne Ausnahme gefüllt ist: anlegen (zunächst nullable),
bestehende Zeilen mit der Standardwährung der Installation füllen, dann auf `NOT NULL`
ziehen. `down()` entfernt die Spalte wieder; beide Richtungen sind gegen die
Testdatenbank geprüft, einschließlich des Backfills einer Bestandszeile.

**Neue Config-Keys:** keine — die Vorgabe kommt aus `config('app.default_currency')`,
der Standardwährung von SaaSykit. Ein eigener Schlüssel wäre eine zweite Quelle für
dieselbe Aussage.
